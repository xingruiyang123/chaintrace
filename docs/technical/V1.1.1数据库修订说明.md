# 链迹追踪数据库 V1.1.1 修订说明

## 修订范围

本版本针对《V1.1_数据库静态复核意见.md》提出的 P0 数据正确性问题进行小版本修订，不改变 V1.1 的主体实体模型。

## P0 修订状态

| 问题 | V1.1.1 处理 |
|---|---|
| `candidate_match.run_id` 可跨案件引用 | 改为 `FOREIGN KEY (case_id, run_id) REFERENCES analysis_run(case_id, run_id)` |
| `money_event.parent_event_id` 可跨案件引用 | 改为 `FOREIGN KEY (case_id, parent_event_id) REFERENCES money_event(case_id, event_id)` |
| `EVENT_TO_CLAIM` 实际连接 EVENT 与 EVIDENCE | 增加 `CLAIM` 图节点，并增加数据库触发器校验匹配类型与两端节点类型 |
| 冒烟数据被标为真实来源 | 所有手工构造来源统一 `is_simulated=true` |
| 原始记录使用占位哈希 | 使用 `pgcrypto.digest(..., 'sha256')` 按实际 JSONB 内容计算并校验 |
| 证据标记为完整但没有真实文件 | 使用 `integrity_status='PENDING'`，避免虚假完整性结论 |
| 链上转账与平台内部充值混成一个事件 | 分别建立 `ONCHAIN_TRANSFER` 和 `EXCHANGE_DEPOSIT`，使用 `RECONCILES_WITH` 候选关系核对 |
| 重复导入链上事件 | 增加按案件、网络、交易哈希、索引、资产和账户端点组成的部分唯一索引 |

## 测试补充

`db_smoke_test_v1_1_1.sql` 新增：

- 跨案件 `analysis_run` 负向测试；
- 跨案件父事件负向测试；
- `EVENT_TO_CLAIM` 节点类型正向验证；
- 链上事件与平台入账事件分离验证；
- 模拟来源隔离验证；
- 原始记录 SHA-256 实值校验；
- 重复链上事件导入拦截验证。

## 未在本版本实现

- `monitor_alert.event_id` 的案件级复合外键；
- `case_access` 对所有业务表的实际 RLS 策略；
- 非所有者数据库角色、TRUNCATE 权限和外部审计归档；
- 跨币种兑换的双币种会计分录。

这些属于 P1/生产部署工作，不阻塞算法一的规则版实验。

## 验收边界

当前环境没有运行中的 PostgreSQL 服务和 `psql` 客户端，因此本版本已完成源码静态校验和测试逻辑检查，但不能声称 PostgreSQL 实际执行已经通过。正式验收仍需在 PostgreSQL 15+ 环境依次执行：

```text
schema_v1_1_1.sql
db_smoke_test_v1_1_1.sql
```
